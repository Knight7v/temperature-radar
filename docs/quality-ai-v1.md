# 客服质检 AI 打分方案

> 当前规则版本 `achat-text-v2` · DeepSeek `deepseek-chat` · 2026-10-19（v1 同日，v2 为首次真实数据校准后的版本）

## 一、从《6.18 日 UA 质检日报》里读出来的规则

模板有 3 个 sheet，真正定义标准的是 `售后新质检`（68 条细则），`会话` 是 144 行的打分记录。我把 144 行逐行对了一遍，还原出实际在用的公式：

```
QA 成绩 = 0.7 × 关键准确率 + 0.3 × 非关键准确率
关键准确率 ∈ {0, 1}   —— 12 个 1/0 项里只要有 1 项记 0，整块 70 分全丢（一票否决）
非关键准确率 = 9 个 5 分制项的平均分 ÷ 5  —— 记为 N/A 的项不进分母
```

验证：`QA 成绩 = 0.96` 的那行，关键项全过、语言表达打 1 分，`(5+5+5+1+5+5)/6/5 = 0.8667`，`0.7 + 0.3×0.8667 = 0.96`，对得上；`QA 成绩 = 0.3` 的 10 行，全都是某个 1/0 项记 0，`0 + 0.3×1 = 0.3`，也对得上。

这套骨架可以照搬，但有两处必须改：

| 模板做法 | 问题 | 本方案 |
| --- | --- | --- |
| 高压线只扣 70 分，最低还有 30 分 | 辱骂顾客还能拿 30 分，不合理 | 红线单独拆出来，命中整单 0 分 |
| 含语音项（语调语速、Hold 线、OB 体验） | 格力/海尔是京东天猫文字客服，没有录音 | 语音项不适用，换成在线客服的对应能力项 |

## 二、打分机制

满分 100 = 关键项 70 + 非关键项 30。

### 红线（命中即 0 分）

| 项 | 判定要点 |
| --- | --- |
| 辱骂攻击 | 侮辱、嘲讽、威胁、驱赶；"我不是跟你说了吗"式质问 |
| 泄露隐私 | 手机号/地址外发、含个人信息截图外传 |
| 虚假承诺/站外交易 | 引导加微信私下转账、承诺"保证明天到"、承诺平台没有的补贴赠品 |

### 关键项（8 项，任一项不合格 → 70 分全扣，本单最高 30 分）

| 项 | 判定要点 | 不适用条件 |
| --- | --- | --- |
| 平台高压线 | 好评返现、刷单、虚假发货、引导删差评、擅自承诺赔付 | — |
| 服务礼仪 | 礼貌用语、称呼、不打断、不命令式 | — |
| 响应时效 | 首响 ≤60 秒，单次等待 ≤120 秒，末条未回复 | 缺时间戳 |
| 信息准确性 | 匹数/能效/适用面积/内外机型号/价格/国补/安装费/保修 | 未涉及参数与政策 |
| 流程合规 | 退换货、报修、安装预约、发票、纠纷按流程登记升级 | 纯选购咨询 |
| 问题解决 | 核心问题是否解决、能否一次解决 | 顾客主动结束且已明确答复 |
| 投诉与敏感诉求 | 提及投诉/315/工商/媒体先安抚再报备 | 全程无不满表达 |
| 沟通逻辑 | 需求理解正确、答复前后一致 | — |

### 非关键项（6 项 × 5 分 = 30 分，5/3/1 制）

| 项 | 5 分 | 3 分 | 1 分 |
| --- | --- | --- | --- |
| 开场与结束语 | 问候自然+身份说明，结束完整礼貌 | 缺身份说明或收尾生硬 | 无开场或无结束语 |
| 语言表达 | 简明有条理、无错别字 | 偏啰嗦或大段模板 | 表达混乱难懂 |
| 服务主动性 | 主动补充关键提醒 | 问什么答什么 | 只回"是的""没有" |
| 共情与情绪管理 | 及时致歉安抚致谢 | 有礼貌无情绪回应 | 全程冷漠机械 |
| 需求确认与销售意识 | 主动确认面积/匹数/能效并推荐 | 有询问但推荐不具体 | 不询问直接甩链接 |
| 收尾与跟进承诺 | 确认无其他问题+给时间方式 | 有收尾未确认 | 无收尾直接中断 |

非关键得分 = Σ实得分 ÷ (5 × 适用项数) × 30。记为"不适用"的项从分母剔除。

### 等级

| 分数 | 等级 | 含义 |
| --- | --- | --- |
| 95–100 | A+ 优秀 | 可作标杆话术 |
| 85–94.9 | A 良好 | 常规合格 |
| 70–84.9 | B 达标 | 有改进项 |
| 40–69.9 | C 待改进 | 关键项失分 |
| 0–39.9 | D 不合格 | 红线或关键项全面失守，含模板的"0.3 封顶" |

一次性解决率、咨询类型单独统计，不进会话分。

## 三、AI 怎么打分（核心设计）

### 一条硬原则：模型只判定、不计算

让大模型直接"给个分"有三个问题：同一个会话两次调用可能差 10 分、算错了看不出来、口径变了要重新教。所以拆成两半：

```
模型输出：每一项 pass / fail / na + 证据（消息编号 + 原文片段）+ 置信度
系统计算：按第二节公式算出总分
```

好处：分数永远可复算、可审计；换模型（chat → reasoner）不影响算分口径；口径调整只改 `rubric.js`。

### 四步流程

| 步骤 | 做什么 | 失败时 |
| --- | --- | --- |
| 1 客观事实 | 代码从时间戳算出首响、最长等待、末条是否未回复、投诉词命中 | 缺时间戳则响应项判不适用 |
| 2 分类 | 先判断咨询类型（售前/价格/订单/物流/安装/售后/退换货/发票/投诉） | 分类失败 → 退化为全部规则适用，不阻断 |
| 3 逐项判定 | 只带"该类型适用的规则"，附会话原文（带消息编号） | 重试 2 次（429/5xx/超时） |
| 4 证据校验+算分 | 见下面三道闸 | — |

### 三道防幻觉闸门

| 闸门 | 规则 | 效果 |
| --- | --- | --- |
| ① 消息编号 | messageId 必须在本次会话里真实存在 | 编造编号直接作废 |
| ② 原文比对 | quote 必须是该条消息原文的连续片段（忽略空格标点差异） | 编造原话直接作废 |
| ③ 置信度 | fail 且置信度 <0.6，或关键项 pass 但置信度 <0.5 | 降级"待复核" |

被降级的项**不扣分**，只在界面上标"待复核"并写清原因。这样做的取舍是：宁可漏判，不可错判——AI 误扣一个关键项，客服直接掉到 30 分，代价远大于漏掉一次。

### 隐私处理

送进模型前，手机号、6 位以上长数字统一替换为**等长星号**。等长很关键：原文和提示词用同一套脱敏规则，证据引文才能继续做子串比对。

## 四、人工怎么配合

AI 全检，人工只复核需要看的三类：

| 复核对象 | 原因 |
| --- | --- |
| AI 判"不合格"的 | 关键项一票否决，必须人确认 |
| 标"待复核"的 | 证据不足或置信度低 |
| 随机 5% 的合格会话 | 监控 AI 是否"放水" |

按经验，人工复核量能压到 20–30%，剩下 70% 是明确合格的。建议每月抽 50 条做人工双盲，算 AI 与人工的一致率；低于 80% 就调提示词或规则口径，别急着上自动化。

## 五、成本

单会话约 1200 prompt token + 420 completion token（含分类调用），按 DeepSeek 现价：

| 量级 | 单次成本 | 说明 |
| --- | --- | --- |
| 单会话 | 约 0.005–0.01 元 | 含分类 + 判定两次调用 |
| 100 通/天 | 约 0.5–1 元/天 | 人工质检 100 通约需 8–12 小时 |
| 3000 通/月 | 约 15–30 元/月 | 全量而非抽检 |

会话超过 80 条时自动保留首尾各 40 条并标注截断，避免长会话把成本顶上去。

| 文件 | 作用 |

| `lib/quality/ai/analyze.js` | 编排（分类 → 判定 → 校验 → 算分），批量并发 3 |

| `lib/db/migrations/0009_quality_ai.sql` | `quality_ai_results` 结果表 |

页面位置：客服质检页 →「AI 质检（DeepSeek）」卡片可看统计与批量分析；点开任一会话，机器预评分下方就是 AI 明细（分数、等级、逐项判定、证据可点击定位原文）。

原来那套"聊天行为机器预评分"（`lib/quality/machine-score.js`，满分 100 扣分制）保留不动，作为导入时的快速筛查；AI 质检是新增的一层，两者互不覆盖，主管评分仍是最终结果。

## 七、启用步骤

1. 到 https://platform.deepseek.com 创建 API Key；
2. 打开项目根目录 `.env.local`，把 `DEEPSEEK_API_KEY=` 后面填上 Key；
3. 重启工作台（双击桌面「启动工作台」）；
4. 客服质检页会显示「已连接 deepseek-chat」；没填 Key 时整块显示"未配置"，不影响原有功能。

## 八、风险与待办

| 项 | 说明 |
| --- | --- |
| 事实类判定要外部数据 | 价格、国补、库存、订单状态 AI 看不到，只能判"话术是否含糊/自相矛盾"，判不了"报的价对不对"。要判准得接商品库和订单接口 |
| 参数准确性依赖规则库 | 建议把主推机型的匹数/能效/适用面积做成对照表喂给模型，否则只能按常识判断 |
| 一致性需持续校准 | 首月建议人工双盲 50 条/月，一致率 <80% 调整口径 |
| 长会话会截断 | 超过 80 条只保留首尾，超长会话建议人工优先 |
| 结果不自动改主管评分 | AI 分只作为建议值展示，避免"AI 说什么就是什么" |

## 九、v2 真实数据校准记录（2026-10-19）

接入真实 Key 后先跑了一轮，结果和人工口径差得太远，做了三处校准。

### 1. 先量了人工口径

《6.18 日 UA 质检日报》141 行有效打分：

| 指标 | 数值 |
| --- | --- |
| 平均 QA 成绩 | **0.950** |
| 满分（1.0） | 128 行，占 **90.8%** |
| 关键项挂 0（→0.3 分） | 13 行，占 **9.2%** |

结论：人工质检极松，九成会话是满分。

### 2. v1 首跑的偏差

同样 10 条会话，v1 给出 **6 条 D 级**（平均 24.6 分），明显过严。逐项看，误伤集中在：

| 误伤点 | 表现 | 原因 |
| --- | --- | --- |
| 问题解决 | 客服已答"目前没有国补"，仍判不合格 | 旧口径要求"给出后续路径"，把否定答复当未解决 |
| 红线/高压线重叠 | 晒图返现同时命中 `redline_fraud` 和 `hotline` | 虚假承诺定义里含"非官方政策"，与平台高压线重叠 |
| 非关键项偏低 | 大量打 1 分 | 缺少"默认 5 分"的基线约束 |

### 3. v2 改了什么

| 改动 | 内容 |
| --- | --- |
| 问题解决判定 | 只有「顾客追问 ≥2 次未答」「答非所问」「推诿且无后续」才判不合格；**否定答复（"没有""不支持"）算已答复** |
| 扣分置信度分级 | 红线 0.85 / 关键项 0.7 / 非关键项 0.5，不到线降级"待复核"，不扣分 |
| 红线与高压线切开 | `redline_fraud` 只管站外交易与明知不可兑现的承诺；好评返现、非官方补贴归 `hotline`（关键项，扣 70 不归零） |
| 判定尺度写进提示词 | 默认立场"合格"；非关键项默认 5 分；校准基线「约七成会话应 ≥85 分，D 级不超过两成」 |

### 4. v2 结果

| 指标 | v1 | v2 |
| --- | --- | --- |
| 平均分 | 24.6 | **60.7** |
| A / B | 1 | 6 |
| D | 6 | 4 |

剩下的 4 条 D 都是**真实问题**，不是误判：

- 3 条同一客服（售前-阿伟）在开场就承诺"直播间下单 晒图评价 每台返100"，命中好评返现高压线——这是公司政策层面的合规风险，不是话术问题；
- 1 条顾客最后问"有没有性价比高一点的"，客服**直接没回复**，会话中断。

### 5. 实测成本

10 通会话合计 51,074 tokens，平均 **5,107 tokens/通**。按 deepseek-chat 现价折算，100 通/天约 1 元以内。
