# 客服质检 · 消费者洞察说明

> 2026-10-26 上线。位置：客服质检页「AI 分析明细」下方新增一段「消费者洞察」。
> 代码：`lib/quality/insight/`（口径与提示词）、`handlers/quality-insight.js`（接口）、`js/quality-insight.js`（页面）。
> 改口径只改 `lib/quality/insight/taxonomy.js`，改完必须升 `VERSION`。

## 一、它和质检不是一回事

| | 客服质检 | 消费者洞察 |
|---|---|---|
| 回答的问题 | 这一单该打几分、谁做得差 | 顾客到底在问什么、我们哪里没答好 |
| 输出 | 100 分制 + 19 项判定 + 等级 | 问题清单 + 主题分布 + 答复缺陷 + 行动建议 |
| 数据表 | `quality_ai_results` | `quality_insights` |
| 用途 | 考核、复核、罚分 | 改进话术、补详情页、排培训、看需求 |

两套结果各自独立存放，互不覆盖，可以分别重跑。同一段会话既能有质检分，也能有洞察记录。

## 二、页面看三件事

1. **顾客问了什么**：按 17 个主题排名（安装条件与费用、功能参数、选购对比、价格与活动、国补…），每条带「没答清比例」和一句真实原话。点一条可以筛出对应问题清单。
2. **客服哪里没答好**：12 类缺陷按条数排名，红/橙/灰对应严重程度。
3. **哪些问题没闭环**：逐条列出没答清的问题，带顾客原话、客服说法、责任人会话，点「看原文」直接跳到聊天记录。

再往下是「按客服对比」和「洞察总结与行动建议」。

## 三、口径（写死在代码里，改这里只改一处）

**阶段**：售前 / 售后 / 混合 / 无可分析内容。按会话主问题归类，不是按客服昵称。

**主题 17 类**
售前：选购对比、功能参数、价格与活动、国补与以旧换新、套装与多台搭配、安装条件与费用、库存与发货时效、赠品与附加服务、发票
售后：物流异常、安装预约与进度、安装收费争议、故障维修、退换货与退款、质保与保修范围、国补核销与退回、投诉与升级
兜底：其他

**答复缺陷 12 类**（严重度只用于排序，不参与打分）

| 严重 | 中等 | 轻 |
|---|---|---|
| 未回复、只答一半、答非所问、口径含糊、信息可能有误、未闭环、未核实就承诺 | 缺操作步骤、未追问澄清、只推单不解惑、响应慢且无说明 | 模板刷屏 |

**「没答清」怎么算**：一条顾客问题被判为「没答」（no）或「答了一半」（partial）才算没答清；「看不出」（unknown）单独统计，不计入分子。所以 38.7% 这个数只统计原文能看出缺口的。

**防幻觉三道**：
① 顾客问题必须挂在真实存在的顾客消息编号上，编号不存在就回落到最近一条顾客消息，绝不凭空生成；
② 顾客原话、总结、建议统一做手机号/长数字等长星号脱敏；
③ 判不出来一律 unknown，不许猜政策、不许替平台规则下结论。

模型给了「答了一半/没答」却没说缺在哪，系统自动记成「未说明不足」并标待复核，不会静默算成已解决。

## 四、首批数据结论（2026-03-25，703 通会话 / 1688 个问题）

- 覆盖 100%（703 通全部分析完），售前 607 通、售后 86 通、混合 10 通。
- 1688 个问题里 654 个没答清，占 **38.7%**；359 通会话至少有 1 处答复缺口（51.1%）。
- 问得最多：安装条件与费用 312 条（196 通）、功能参数 233 条、选购对比 232 条、价格与活动 227 条。
- 答得最差：口径含糊 298 条（200 通）、未闭环 147 条、缺操作步骤 121 条、未回复 93 条、答非所问 92 条。
- 顾客最担心：怕安装加钱 194 条、怕买贵 160 条、怕到货或安装太慢 95 条、怕拿不到补贴 86 条。
- 按客服：售后-鹿鹿 24 通未答清率 80%（样本小）；售前小雪 44.9%、小星 42.6%、阿伟 38.6%、01 32.4%、婷婷 26.8%。

这些数字是「问题条数」口径，不是「会话及格率」，不要拿去和质检分直接对比。

## 五、怎么用

- **范围**：跟随页面上方「分析日期」，不再单独放日期框——改一次日期，总览 / 会话 / 消费者洞察三个视图一起换。上方留空 = 全部日期。点「范围：X」这个标签会把光标带回上面的日期框。
- **开始分析**：每批 25 条，自动连续跑，随时可停；已分析的会跳过，再点一次接着跑。
- **筛选**：阶段 / 主题 / 缺陷 / 客服四个条件叠加，点上面的条形图也能直接筛。
- **导出**：CSV，一行一个问题（客服、时间、顾客问题、主题、是否答清、缺陷、说明、顾虑、结论），Excel 直接打开。
- **生成总结**：把上面的统计交给模型写一段结论 + 4-6 条带责任岗位和优先级的行动建议。同一批数据 6 小时内不重复生成，数据变了会自动失效。

**成本与耗时**：703 通实测约 5.5 分钟、输入约 150 万 token（按 DeepSeek 现价几元）。总结每次约 4000 token。

## 六、命令行补跑（页面嫌慢时）

```bash
node scripts/quality-insight-run.js --limit 40 --dry        # 试跑不入库，先看模型判断准不准
node scripts/quality-insight-run.js                          # 跑完所有还没分析的
node scripts/quality-insight-run.js --date 2026-03-25 --concurrency 4
```

`--dry` 只在终端打印结果，方便先校准提示词再入库。

## 七、已知局限（别当结论用）

- 模型判断的是「原文能否看出缺口」，需要订单/物流/政策系统才能确认的，一律 unknown，所以真实缺口可能比 38.7% 更高而不是更低。
- 「口径含糊」是最容易误伤的一类：客服已经给了数字但没给构成，可能被判 partial。抽查发现这批评判基本站得住，但对外汇报前建议人工抽查 10 条。
- 会话中间被截断的长会话（超过 80 条消息）只依据可见部分判断，结果带 `warnings` 提示。
- 顾客情绪、成交/未成交只作参考，模型看不出来会给 unknown。
