# 空调热销区域雷达「深色钛金」全站视觉改造设计

**日期：** 2026-07-24
**状态：** 已完成设计讨论，等待书面规格确认
**范围：** 全站视觉设计系统重构与适度布局重排
**技术栈：** 原生 HTML、CSS、JavaScript、ECharts

## 1. 背景与目标

当前界面采用深蓝霓虹数据大屏风格，存在颜色过多、发光效果偏重、字体带有游戏感、组件规则不统一等问题。本次改造采用已确认的「深色钛金」方向，将全站升级为接近 Apple Pro 产品页与专业数据工作台结合的视觉体验。

改造目标：

1. 建立覆盖全站的统一设计令牌和组件规范。
2. 使用近黑背景、半透明玻璃材质、冷银高光和克制的局部能量色。
3. 在保留现有功能与数据逻辑的前提下，适度调整信息层级和页面布局。
4. 优先优化 1440px–1920px 桌面大屏体验，同时保证平板和手机端可操作。
5. 提升可访问性、交互反馈和视觉一致性。

## 2. 已确认的设计决策

- 视觉方向：深色钛金。
- 覆盖范围：全站统一改造。
- 改造深度：设计系统重构，加适度布局重排。
- 主要设备：桌面大屏优先。
- 技术策略：保留原生技术栈，不引入 React、Vue 或额外 UI 框架。
- 业务边界：不重写天气计算、ADI 算法、认证、支付或数据模型。

## 3. 视觉设计系统

### 3.1 色彩

| 用途 | 色值 |
|---|---|
| 页面底色 | `#08080A` |
| 一级容器 | `rgba(28, 28, 30, 0.78)` |
| 二级容器 | `rgba(44, 44, 46, 0.64)` |
| 主文字 | `#F5F5F7` |
| 次级文字 | `#A1A1A6` |
| 弱化文字 | `#6E6E73` |
| 品牌高光 | `#5E8DFF` |
| 成功状态 | `#30D158` |
| 警告状态 | `#FF9F0A` |
| 高风险状态 | `#FF453A` |

状态色只用于表达业务含义。地图热区、核心指标和预警可以使用局部能量色，普通容器、导航和装饰不得使用大面积彩色发光。

### 3.2 材质

- 页面背景采用近黑色，并可使用低透明度径向渐变增加空间层次。
- 侧边栏与顶部栏采用高模糊半透明玻璃材质。
- 数据卡片采用低透明钛金渐变、极细银灰描边和深色环境阴影。
- 普通卡片不使用彩色外发光。
- 圆角分为 10px、16px、22px 三档：
  - 10px：输入框、小按钮、标签。
  - 16px：数据卡、工具栏、表格容器。
  - 22px：大型面板和模态框。

### 3.3 字体与数字

字体栈：

```css
-apple-system, BlinkMacSystemFont, "SF Pro Display", "PingFang SC",
"Helvetica Neue", Arial, sans-serif
```

- 移除 `Orbitron`，避免游戏化视觉。
- 页面结论标题使用 32–44px。
- 页面主标题使用 24–32px。
- 正文不低于 14px。
- 表格正文约 13px。
- 核心数字使用紧凑字距和 `font-variant-numeric: tabular-nums`。

### 3.4 图标

- 导航、操作按钮和状态入口使用同一套单色 SVG 线性图标。
- 移除导航与通用操作中的 Emoji。
- 业务含义图标，如热夜、降水、趋势，需要使用一致的 SVG 图标替代。
- 图标默认银灰色，选中时为白色或冷银蓝。
- 图标按钮必须包含可访问名称。

### 3.5 动效

- 页面切换：220ms 淡入并上移不超过 8px。
- 悬停：仅改变亮度、描边和阴影，不使用明显缩放。
- 模态框：背景模糊加轻微缩放进入。
- 控件状态切换：150–220ms。
- 必须支持 `prefers-reduced-motion`，关闭非必要位移和循环动画。

## 4. 全局框架

### 4.1 桌面布局

- 侧边栏宽度约 200px，使用悬浮玻璃材质。
- 顶部栏降低高度与视觉噪声，保留页面标题、更新时间和关键指标。
- 内容区域最大宽度约 1600px，在超宽屏幕中居中展示。
- 首页采用 12 栏网格。
- 其他页面采用统一的“页面标题区—工具栏—内容容器”结构。

### 4.2 导航

- 保留现有主导航与分析子导航的业务结构。
- 使用统一 SVG 图标。
- 当前页面使用半透明亮面背景、白色文字和冷银蓝提示。
- 折叠、展开和键盘焦点状态必须明确。
- 系统状态保留在侧边栏底部，使用小型状态点和简短文字。

### 4.3 顶部栏

- 左侧显示当前日期和页面标题。
- 右侧显示监控城市、爆热、热夜城市等关键指标。
- 指标默认使用中性色，仅异常或重点数据使用状态色。
- 小屏幕下按优先级隐藏次要指标。

## 5. 页面设计

### 5.1 销售总览

信息结构：

1. 顶部显示大结论，例如“今天，机会很强。”
2. 左侧显示销售机会强度和重点区域排行。
3. 中间显示全国热力图，作为页面视觉核心。
4. 右侧显示重点城市榜单。

具体规则：

- 原“今日判断结论”改为简短行动摘要。
- 地图维度切换使用分段控制器。
- 地图容器保留现有 ECharts 功能，只调整配色、Tooltip 和容器样式。
- 城市榜单减少重复标签，突出城市、区域、等级和 ADI。

### 5.2 热销分析

- 保留夜间闷热、未来 3 天、未来 7 天、重点城市群四个子页面。
- 表格统一使用玻璃数据表样式。
- 排名前三名分别以银色、钛金色和暖铜色轻量强调。
- 城市群监控采用左侧区域切换、右侧指标与表格的双栏布局。
- 页面结论使用顶部洞察卡，减少多层卡片嵌套。

### 5.3 7 天预测

- 搜索、维度切换和区域筛选合并为吸顶工具栏。
- 表格保留横向滚动和固定列。
- 表头使用半透明深色背景和模糊效果。
- 温度、ADI、投保提醒使用低饱和状态色，避免大面积整格高亮。
- 日期列保持清晰的周期节奏。
- Tooltip 使用玻璃浮层，统一呈现温度、湿度、天气和销售等级。

### 5.4 降水监控

- 与 7 天预测共享工具栏、表格容器和 Tooltip 视觉骨架。
- 投保提醒和雨后湿热使用同一套分段控制器。
- 强提醒、提醒、无提醒，以及高、中、观察状态使用一致的状态徽标。
- 不改变降水计算规则。

### 5.5 规则设置

- ADI 等级说明改成五段水平状态带。
- 权重、等级阈值、强制升级规则、热夜规则分别放入独立设置分组。
- 数字输入使用 macOS 风格控件和清晰焦点描边。
- 保存操作放入底部吸附操作栏。
- 操作栏需要展示“已保存”或“存在未保存修改”状态。
- 本次只实现视觉与前端状态表达，不新增后端持久化能力。

### 5.6 城市详情与今日简报

- 城市详情使用居中大型玻璃面板。
- 核心指标位于顶部，趋势表格位于下方。
- 今日简报保留管理层版和运营版切换。
- 复制、关闭等操作使用统一按钮体系。

### 5.7 登录、微信与支付

- 登录弹窗减少装饰，突出手机号和验证码输入。
- 微信登录区域使用标准二维码占位容器，不使用 Emoji。
- 支付方案使用两张定价卡，清晰强调推荐方案。
- 当前认证和支付后端能力不在本次重构范围内；视觉改造不得暗示尚未实现的功能已经可用。

### 5.8 系统反馈

- Toast、加载、错误、空状态和确认提示使用统一浮层体系。
- 全屏加载改为银色进度与简洁品牌标识。
- 表格和榜单加载时预留稳定空间，避免内容跳动。
- 错误信息需提供明确文案，避免只显示颜色或图标。

## 6. 可复用组件

| 组件 | 用途 |
|---|---|
| `glass-panel` | 页面主容器和大型卡片 |
| `metric-card` | 关键指标卡 |
| `segmented-control` | 地图和预测维度切换 |
| `status-badge` | ADI、温度、降水和权限状态 |
| `data-toolbar` | 搜索、筛选和操作区域 |
| `data-table-shell` | 统一表格外壳 |
| `modal-surface` | 详情、登录、支付和简报弹窗 |
| `primary-button` | 主要操作 |
| `secondary-button` | 次要操作 |
| `ghost-button` | 轻量操作 |

组件必须覆盖默认、悬停、按下、禁用和键盘焦点状态。

## 7. 响应式策略

### 1440–1920px

- 完整三栏首页。
- 顶部指标完整显示。
- 表格最大化使用可用空间。

### 1024–1439px

- 首页调整为地图优先的两栏布局。
- 重点城市榜单可下移。
- 次要顶部指标按优先级隐藏。

### 768–1023px

- 侧边栏折叠为图标栏。
- 内容改为单列或双列。
- 表格继续横向滚动。

### 小于 768px

- 导航切换为紧凑顶部入口或抽屉。
- 卡片单列堆叠。
- 表格保持横向滚动和固定关键列。
- 移动端目标为可用，不要求与桌面端相同的信息密度。

## 8. 交互规则

- 保留现有单页导航方式。
- 所有可点击元素显示指针样式和视觉反馈。
- 最小点击区域为 44×44px。
- 表格行悬停只改变背景亮度，不产生位移。
- 分段控制器状态变化必须立即可见。
- 弹窗支持关闭按钮和点击遮罩退出。
- 键盘焦点使用高对比度外框，不得仅依赖颜色变化。
- 业务状态不能只通过颜色表达，必须同时显示文字或图标。

## 9. 技术方案与边界

主要修改文件：

- `index-v2.html`
- `css/styles-v2.css`
- `js/ui.js` 中动态生成的类名、图标和少量结构
- 必要时调整 `js/map.js` 的颜色与 Tooltip 配置

实施原则：

- 不引入新前端框架。
- 不修改天气计算、ADI 算法或数据模型。
- 不扩展认证、支付和权限后端。
- 不处理与视觉验收无关的历史代码重构。
- 若现有运行时错误阻碍页面视觉验收，只做最小修复并单独记录。

## 10. 测试与验收

### 10.1 视觉验收

- 五个主业务页面以及城市详情、简报、登录、支付等界面使用同一设计语言。
- 视觉结果与已确认的「02 深色钛金」稿保持一致。
- 不保留传统蓝色霓虹大屏风格和 `Orbitron` 字体。
- 颜色、间距、圆角、阴影、图标和按钮状态保持一致。

### 10.2 布局验收

- 1920×1080 和 1440×900 下无内容遮挡或非预期滚动。
- 1024px 宽度下导航、地图、筛选和表格仍可操作。
- 小屏幕下内容不溢出视口，允许数据表格在自身容器中横向滚动。

### 10.3 可访问性

- 普通文本对比度达到 WCAG AA 基本要求。
- 交互控件具有可见焦点状态。
- 图标按钮具有可访问名称。
- 状态不只通过颜色表达。
- 支持 `prefers-reduced-motion`。

### 10.4 功能回归

- 页面导航正常。
- 地图维度切换正常。
- 首页榜单切换正常。
- 预测和降水维度切换正常。
- 搜索和区域筛选正常。
- 城市详情和今日简报弹窗正常。
- 规则设置控件仍可交互。
- 不新增浏览器控制台错误。

### 10.5 非目标

以下内容明确不属于本次验收范围：

- 真实短信服务。
- 真实微信登录。
- 真实支付平台接入。
- 权限后端和数据库持久化。
- 天气或 ADI 算法调整。
- 修复所有既有业务缺陷。
