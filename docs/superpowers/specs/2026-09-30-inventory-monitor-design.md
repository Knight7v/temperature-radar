## 1. 目标与范围

用户补充整体目标：将现有项目升级为公司的工作台，集成气温监控预警（原有功能）、库存监控预警、客服质检和视觉设计（AI 生图、生视频）。本规格详细定义已完成需求讨论的库存模块；不将客服质检和视觉设计的技术、供应商、业务流程或交付时间视为已确定。

通过每日导入京东全仓库存报表，识别缺货风险、滞销、库存积压及空调内外机缺配，支持历史查询和 Excel 导出，每天向固定企业微信群发送摘要和完整日报。

成功标准：同一日期、同一次计算的页面、Excel 和企业微信摘要一致；缺少数据或配置时明确显示原因，不误报为库存正常；使用者无需打开网页，服务端也能执行每日推送。

### 1.1 已确认的业务决定

| 项目 | 决定 |
| --- | --- |
| 数据来源 | 首期导入 ERP／京东导出的 Excel、CSV，接口同步后续再做 |

| 估算成套销量 | 同仓内外机在同一统计周期的销售出库量取较小值；不等时提示异常 |
| 销量周期 | 默认近 7 天，可按商品切换近 15／30 天 |

| 数据未更新 | 只发送未更新提醒及最后数据日期，不发旧日报冒充最新数据 |
| 接入条件 | 用户已有群机器人 Webhook，后续通过配置接入 |
| 权限 | 运营／仓管导入及确认配对；管理员维护规则和推送设置；其他人查看、筛选、导出 |

### 1.2 本规格提出的实施默认值

以下是为了闭合流程提出的设计，随本规格一起审阅，并非用户先前逐项明确指定：

- 导入严格校验，任一阻断错误使整批不生效；异常可下载，修正后重传。
- 每次导入确认全仓完整性；缺失仓库或商品需要显式确认，缺失数据不自动转成零库存。
- 固定规则优先级、零销量与缺配处理、历史计算留存方式见第 4～6 节。
- 默认上传限制为 3 MiB、10,000 条明细、单个非空工作表；部署前按实际接口载荷限制验证。
- 首期管理员可手动重试失败推送或明确补发修正版，系统不因晚导入或修改配置自动追加群消息。
- 无自动历史清理；不提供被替换原始文件的多版本浏览，仅保留操作差异及已发送日报依据。

## 3. 报表字段与导入约定

### 3.1 已检查的样例

文件：`仓储监控-库存快照监控_分仓_2026.09.29-2026.09.29-20260930091416931-万有引力引凤工作台.xlsx`。

样例有 1 个工作表、17 列、58 条明细，日期为 2026-09-29，包含 12 个仓库和 10 个京东 SKU。按日期＋仓库＋京东 SKU 检查，未发现重复记录。周转字段各有 22 条空值，应作为可空原始指标保留。

| 字段 | 处理 |
| --- | --- |
| 日期 | 业务快照日期，按北京时间日历日期解析；不使用上传日期或文件名代替 |
| 仓库名称 | 初次导入登记仓库，后续精确关联；仅清理首尾空白，不模糊合并 |
| 京东SKU | SKU 主标识，按文本保存 |
| 商家商品编码 | 辅助标识，按文本保存，保留前导零 |
| 商家商品标识、商品名称、省市 | 原始描述和展示信息 |
| 在库件数、在库件数-良品、在库件数-残品 | 原始库存分类，不等同于可售量 |
| 可用在库件数 | 独立 SKU 可售库存及成套计算的基础 |
| 销售出库件数 | 当日出库，单独展示 |
| 近7天／近15天／近30天销售出库件数 | 各周期累计销售出库量，用于日均出库和风险计算 |
| 商品MTD周转、30天周转 | 京东原始指标，仅展示，不能当作本系统预计可售天数 |

近 7／15／30 天是有重叠的累计口径，不能彼此相加，也不能跨每日快照求和作为区间销量。源表没有订单、在途库存或成本信息，不推算这些指标。

### 3.2 导入流程

1. 上传 `.xlsx` 或 `.csv`。CSV 首期支持 UTF-8（含 BOM）；其他编码提示转换。拒绝宏文件、旧版 `.xls` 及伪装扩展名。
2. 服务端按表头映射上述字段，允许列顺序变化和额外列，原始额外列可保留；不执行公式、宏或文件中的文字指令。必填字段公式单元格拒绝导入，要求导出为值。
3. 同一文件仅允许一个数据日期，不接受未来日期。关键身份字段、库存和四个销量数值字段必填；数量须为非负整数，空白不等于零。周转及辅助描述允许空值。
4. 同日同仓同 SKU 重复、必填缺失、无效数值、列缺失、库存分类与总量矛盾、可用数大于良品数、滚动累计出库不满足 7≤15≤30 时阻断导入，并标注行列及原因；不得自动修正数据。若真实源报表口径与这些约束不同，应先修订适配定义。
5. 展示日期、仓库数、SKU 数、记录数、各数量汇总及样例；以最近确认的仓库集合提示仓库减少。首次导入由操作者确认已覆盖全仓，系统不能仅凭文件判断是否遗漏仓库。
6. 对已有同日期快照按仓库＋SKU 比较新增、变更、缺失行；展示关键数量的前后值。同文件内容哈希相同则提示无需重复导入。
7. 用户确认全仓范围和替换差异后，在数据库事务内切换完整快照、保存计算结果和操作记录。失败不改变现有有效快照。

预览结果绑定租户、文件内容摘要和目标快照版本，15 分钟内有效；预览后有人更新同日快照或配对／规则时，要求刷新预览，禁止以过期差异覆盖新数据。不同日期的历史记录不受替换影响。

缺失行确认替换后不再属于该日明细，但保留删除差异。配对任一组成 SKU 缺行时标记数据缺失，不能用零代替，更不能推导可售套数。真实零库存必须来自明确的零值记录。

## 4. 商品配对与规则

### 4.1 配对

商品目录区分单品和内外机组合。系统根据名称、型号和明确的对应整机文字提出草稿；草稿不参与套数计算。候选冲突或名称不明确时交由人工选择，不能以名称相似直接确认。

- 一个组合包含一个内机 SKU、一个外机 SKU，各一件；首期不支持一拖多或一个 SKU 同时被多个有效组合分配，以免重复计算可售套数。
- operator／admin 确认、修改配对及单品分类；确认人、时间、旧值和新值留痕。
- 未确认组合的 SKU 显示原始数据及“配对待确认”，仅参与 SKU 口径，不混入整套商品汇总。
- 已确认组合缺少任一原始行时为“数据缺失”；两行都存在、可用量不等时为“内外机缺配”。
- 内外机各周期出库量不等时，保留估算结果，并对相应周期显示出库不一致提醒。

### 4.2 规则配置

管理员配置：销量周期（7／15／30）、补货到仓天数、安全天数、积压上限天数。周期默认 7，其他字段默认空。

字段逐项采用「仓库＋商品覆盖 → 商品默认 → 仓库默认 → 全局默认」优先级。页面展示生效值和来源；空白表示继承，所有层均为空则待配置。补货／安全天数允许明确的 0，不能把 0 当成未配置；积压上限必须大于 0。

组合规则绑定整套商品，SKU 规则绑定独立 SKU，不自动混用。默认日常汇总以已确认整套／单品口径为主；SKU 视图展示零部件风险，但不把两种口径的数量或预警数相加。

## 5. 计算定义和边界

设选定周期为 N，N∈{7,15,30}；可用量为 A，周期出库量为 S，日均出库 D=S/N。

| 指标／状态 | 定义 |
| --- | --- |
| 单品／SKU 可用量 | 原报表可用在库件数 |
| 同仓成套可用量 | min(内机可用量, 外机可用量) |
| 同仓估算成套出库量 | min(内机该周期出库量, 外机该周期出库量) |
| 预计可售天数 T | D>0 时 A/D；保留全精度判定，展示 1 位小数 |
| 缺货风险 | 输入完整、补货与安全天数已配置且 D>0，T < 补货天数＋安全天数 |
| 近30天无销售出库 | A>0 且近30天出库量为0；组合标明依据为估算成套出库 |
| 积压风险 | D>0、上限已配置，T > 积压上限 |
| 内外机缺配 | 两行均存在且可用数量不等；显示多余内机／外机数量 |
| 出库不一致 | 同一周期内外机出库量不等，单独展示原始值和差额 |

判定阈值恰好相等时不触发对应风险。待配置、数据缺失、配对未确认和出库不一致为独立状态，不能被其他标签覆盖。一个商品可以同时有业务预警和数据异常，汇总注明各类计数可能重叠，总风险商品数按仓库＋商品去重。

零销量处理：

- S=0 时预计可售天数为空，显示“近N天无销售出库”，不显示无限天数，不判定基于天数的缺货或积压。
- 选近7天且7天出库为0、30天出库大于0时，不触发30天滞销，不自动切换销量周期。
- A=0、S>0 时 T=0，配置完整后按同一缺货公式判断。
- A=0、S=0 时显示零可用库存与所选周期无出库，不推断存在销售需求，不计为滞销或库存正常。
- 任一组成 SKU 所需值缺失时，依赖该值的成套指标不可计算；显式零与缺失严格区分。
- 组合近30天出库最小值为0但另一组成件有出库时，同时显示“估算成套近30天无销售出库”和出库不一致，不能声称两种零部件都没有销售。

全仓套数先按仓配套再求和，不能先把内外机跨仓求和后取最小值。全仓日均出库由各仓同周期出库汇总后除以 N；仓库使用不同周期时不生成混合口径的全仓可售天数，提示需统一周期。冰箱台数、空调套数和 SKU 件数分开展示。

## 6. 快照、历史与持久化

建议新增以下数据实体，均带 tenant_id，涉及仓库、SKU 和组合的关联须校验归属：

| 实体 | 内容与约束 |
| --- | --- |
| inventory_warehouses / inventory_skus | 稳定内部 ID、源仓库名／京东 SKU、辅助编码与展示名称；租户内唯一 |
| inventory_products / inventory_pairings | 单品或组合定义、草稿／确认状态、版本和确认信息；有效组合的组成 SKU 排他 |
| inventory_rules | 全局／仓库／商品／仓库商品层规则、版本、更新者 |
| inventory_snapshots / inventory_snapshot_rows | 每租户每业务日期一个有效快照；记录文件摘要、导入者、时间、版本；行按快照＋仓库＋SKU 唯一 |
| inventory_calculations | 计算版本、快照版本、配对及生效规则副本、公式版本、结果；完成后不可变 |
| inventory_import_logs / inventory_audit_logs | 导入结果、同日替换差异、配置和配对操作留痕；不存 Webhook 明文 |
| inventory_push_config | 固定群机器人密文、启用状态、北京时间 10:00 配置、更新时间；首期时间固定 |
| inventory_push_runs | 计划执行日、目标数据日、冻结计算版本或缺报状态、摘要／文件发送分项状态、错误及重试信息 |

历史查看使用该日当前有效快照关联的计算版本。修改规则／配对时，自动重新计算最新业务日期的有效快照，并显示刷新时间；更早日期不自动重算。后补历史报表按导入时配置计算并记录配置副本，不冒充当时已知规则。

同日替换创建新计算版本并切换有效快照。操作日志保存变化，旧原始文件不提供多版本查询；已经发送的日报须冻结完整导出所需数据和计算依据，后续快照替换不能改变当时发送内容。旧计算可因审计需要内部保留，但首期不提供多版本浏览界面。

持久化不可变计算版本支持页面、导出和推送引用同一份结果。调度与导入并发时只读取完整提交后的版本，不能读到半批数据。

## 7. 页面及权限

库存模块接入统一工作台导航，首期同时建设第2.3节工作台框架。库存模块沿用现有视觉样式，包含：

1. 库存看板：数据日期和更新时间、全仓完整性、分口径概况、风险分类、待配置／异常计数；日期、仓库、商品、预警筛选；整套与 SKU 切换。
2. 导入中心：上传、校验、全仓范围确认、差异预览、提交、历史操作列表。
3. 商品配对：草稿候选、确认、修改及单品分类；显示来源 SKU 和型号，不隐藏猜测的不确定性。
4. 规则设置：层级覆盖、生效值、销量周期、到仓天数、安全天数和积压上限。
5. 推送设置与记录：Webhook 配置状态、启停、数据日和发送分项结果；管理员可发测试消息及重试／补发，点击发送动作即明确授权，配置保存不自动发消息。

| 动作 | admin | operator（运营／仓管） | viewer |
| --- | --- | --- | --- |
| 查看、筛选、历史查询、导出 | 是 | 是 | 是 |
| 导入、同日替换、配对确认 | 是 | 是 | 否 |
| 规则和推送配置 | 是 | 否 | 否 |
| 测试、重试或修正版补发 | 是 | 否 | 否 |

服务端验证角色及租户，按钮隐藏仅用于界面表达。登录过期要求重新登录，禁止静默退回模拟数据。库存入口必须接入现有账号流程；若前端登录尚未完成，补足库存所需登录态处理。

## 8. Excel 日报与筛选导出

完整日报为一个 `.xlsx`，包含汇总、分仓整套及单品明细、独立 SKU 明细、预警及数据异常清单、规则与口径说明。数据日期、生成时间、计算版本、单位和估算口径明确可见。数值为数值，SKU 为文本；源文件中的文字不能变为 Excel 可执行公式。

汇总包括：仓库覆盖、空调可售套数、单品数量（按品类／单位）、风险商品数、各类预警及待配置／异常数量。选定7／15／30天口径和生效阈值在明细中可查。

筛选导出使用当前日期、口径、仓库、商品和预警条件，标题注明筛选条件；汇总仅统计筛选集合，不混入全仓数量。空结果导出带表头和“无匹配记录”，不能伪装成功生成非空数据。只读用户仅导出本租户授权数据。

## 9. 企业微信日报

### 9.1 每日逻辑

服务端按 Asia/Shanghai 计算当天及前一天，目标是每天北京时间 10:00 启动库存任务。库存任务独立于现有天气任务，使用专门配置的已存在群机器人。

1. 验证调度鉴权，按租户＋北京时间执行日原子获取任务锁并建立运行记录。
2. 检查前一天是否存在已确认完整、成功计算的有效快照。仅文件上传成功不等于快照有效。
3. 无目标日期快照时，只发送未更新提醒，注明应有日期及最近已有数据日期；从未导入则显示暂无数据。不能用今天或更早快照替代昨天。
4. 有有效快照时冻结计算版本及日报数据，生成完整 Excel，再发送库存摘要和文件。摘要包含日期、范围、分口径库存、预警数量、重点项以及待配置／异常计数。
5. 无业务预警仍发送摘要和 Excel；有待配置／异常时表述“暂无已判定预警，仍有待处理项”，不能声称全部正常。
6. 分别记录摘要、文件上传及文件消息结果。日志与页面提供错误和人工重试入口。

Webhook 仅服务端使用，加密存储，页面仅显示已配置及脱敏状态。只接受官方企业微信 HTTPS 机器人地址，禁止任意 URL／重定向和日志泄露密钥。Cron 使用必配 secret 的 Bearer 鉴权，不仅信任可伪造来源头。

### 9.2 文件及失败处理

群机器人文件消息采用“生成 Excel → 上传临时素材 → 发送文件引用”流程，部署联调核实官方协议、文件大小及消息限制；不能只把网页下载链接当作用户已选择的 Excel 附件。

先验证日报生成成功再发送正常摘要，避免摘要成功却根本无法产出文件。文件发送失败时保留摘要成功状态，管理员重试只重发明确失败部分；临时素材失效则重新上传同一冻结日报。

明确收到平台拒绝或限流时记录可重试失败。请求超时且无法判断平台是否接收时标记“发送结果未知”，不盲目自动重发，由管理员核对群消息后处理。外部机器人不提供本系统事务保证，不能承诺绝对恰好一次。

运行锁避免并发重复发送，任务中途退出后可恢复未确认步骤；已成功分项不会再次发送。每天默认一次。10:00 后晚导入或修改快照不自动追加消息；管理员明确补发时标记“补发／修正版”、原数据日期和版本。

附件生成或接口大小超限时明确记录失败，不静默截断日报；首期输入容量设上限，容量验证是部署验收的一部分。消息摘要按官方字节限制裁剪重点明细，完整清单始终保留在 Excel。

### 9.3 调度部署约束

Vercel 现有配置可新增库存任务，但官方文档说明 Hobby 计划仅有小时级调度精度，可能在所设小时内任意时刻执行，不能据此承诺 10:00 启动。

上线必须验证实际部署计划，并配置支持分钟级的调度（符合条件的 Vercel 计划或受鉴权的外部调度器）。不自动升级付费计划或购买服务。若当前环境不满足精度，库存功能可验收，但“每日10:00自动推送”仍视为未验收，不悄悄改成10点这一小时内。

调度启动与网络送达区分记录；正常目标为 10:00 启动、随后完成摘要与附件。不把第三方调度／网络当作严格实时保证。

## 10. 服务边界与接口草案

库存服务分别负责：解析校验、配对、规则求值、纯计算、事务保存、Excel 导出、企业微信传输。日期和计算口径集中实现，避免前端与定时任务各算一套。

| 接口范围 | 责任 |
| --- | --- |
| `/api/inventory/import-preview` / `import-confirm` | 上传校验、差异预览及版本绑定确认；operator／admin |
| `/api/inventory/snapshots` / `overview` | 日期列表、指定计算版本看板与筛选明细 |
| `/api/inventory/pairings` | 草稿、确认、修改，读写权限分离 |
| `/api/inventory/rules` | 生效规则读取与管理员修改 |
| `/api/inventory/export` | 基于已保存计算版本生成完整／筛选 Excel |
| `/api/inventory/push-config` / `push-runs` | 管理员配置、任务查询及明确重试／补发动作 |
| `/api/cron-inventory` | 仅调度鉴权；固定目标日期、锁与发送状态流转 |

接口命名为实现草案，可在开发计划中按现有路由约束调整，不改变业务契约。持久化操作以数据库支持的事务方式实施并通过真实数据库集成测试；不能假设 neon-http 支持任意交互事务回调。

## 11. 验收标准

1. 样例导入预览识别 2026-09-29、12 仓、10 SKU、58 行；17 字段正确映射，周转空值保留。首次样例仅用于测试，不能发送成当前日期日报。
2. 上传无效字段、混合日期、负数、重复主键、公式、超量文件时返回具体原因，旧快照不变；CSV 与 XLSX 等价输入产生相同规范化数据。
3. 同日期替换显示新增／变更／缺失，未确认不修改，过期预览不能覆盖并发更新；提交失败回滚。
4. 甲仓内机10外机0、乙仓内机0外机10，成套总量为0；甲仓内机10外机8时为8套，缺配2内机。缺一行时套数不可计算而不是0。
5. 未确认配对只展示 SKU；已确认配对不能重复占用同一组成 SKU。
6. 周期7天出库14、可用16时日均2、可售8天；到仓5＋安全3时不触发缺货，可用15时触发；积压上限8时8天不触发，大于8才触发。明细舍入不影响判定。
7. 配置空白与0行为不同；零销量、近7天零但30天非零、成套出库差异、数据缺失均按第5节处理，不能显示虚假的正常状态。
8. 历史日期查询／导出重现原规则结果；规则变更刷新最新日期，旧日期不自动变化；已发日报不因同日替换改变。
9. viewer不能导入或改规则，operator不能改管理员配置；跨租户的ID、预览令牌、导出和推送均无法访问。
10. 页面、Excel及推送摘要使用同一计算版本，整套／SKU计数不重复合并；筛选导出和空结果正确，工作簿布局清晰且编码不变形。
11. 固定北京时间测试覆盖月末、年末及服务器UTC时区；有昨日有效数据则即使无预警也发摘要和文件，无昨日数据只发未更新提醒。
12. 并发触发只创建一个默认日任务；模拟附件失败、素材失效、限流、超时未知和进程退出，重试遵守分项状态。
13. 在可用数据库上完成事务、隔离、幂等与权限集成验证；现有天气功能和测试无回归，Vercel构建通过。
14. 使用明确授权的测试群验证摘要、真实Excel附件和失败记录；上线环境证明分钟级调度可用、所需密钥及数据库已配置，验证不依赖浏览器打开。
15. 工作台首页正确呈现四个模块；气温和库存进入可用页面，客服质检和视觉设计清晰显示规划中，不产生真实质检或生成请求。
16. 登录、退出、过期返回及深链接行为正确；气温旧链接可用，原有地图和交互无回归；桌面与移动端导航可达，查看用户不能绕过按钮限制执行写操作。

本阶段只编写规格，不迁移数据库、不接入真实Webhook、不发送群消息、不部署产品。
