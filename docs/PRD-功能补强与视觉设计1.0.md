> 版本 v1.0 · 2026-10-27 · 状态：待评审 · 适用：内部自用（格力/海尔空调分销）

## 0. 文档说明

本 PRD 分两部分：

- **第一部分（第 1—3 章）**：工作台整体补强路线，来自 10-27 的整体评估（77 分）与开源对标，**后期排期实现**。

## 1. 背景与结论

### 1.1 现状一句话

工作台已经能回答「卖了多少」和「客服答得好不好」，但回答不了「赚了多少」，也没有把「发现的问题」变成「谁去解决」。视觉设计板块已有可用的合成引擎，但 AI 只输出背景、场景只有 8 张内置图，离「运营自己就能出图」还差一层。

### 1.2 已确认的三条口径（2026-10-27）

| 事项 | 决定 | 影响 |
|---|---|---|
| 库存模块 | **不作为版本核心，优先级下调** | 不再追每日快照与补货计划，页面保留可用即可 |
| 人工盲评 | **暂缓**，稍后做 | 校准页保留，不催办、不代填 |
| 主线 | 转向**实用性补强**，视觉设计先行 | 见第 3、4 章 |

### 1.3 本期要解决的核心问题

视觉设计现在的问题是「能用，但不像生产线」：

- 运营要出一套图（1 张首图 + 4 张场景 + 1 张活动图），现在要手工重复 6 次，每次重新选场景、重写提示词、重新下载。
- 没有素材库，出过的图散落在 `assets/design/generated/`，200 张后自动淘汰，找不回来。
- 没有审核状态，谁出的、能不能上架、有没有违规，全靠人记。
- 场景只有 8 张内置图，AI 生成要手动配 Key，普通运营不敢点。

## 2. 目标与非目标

### 2.1 目标（1.0）

| 目标 | 可衡量标准 |
|---|---|
| 一套图从 40 分钟降到 10 分钟 | 运营实测：1 个 SKU 产出 6 张可用图 ≤ 10 分钟 |
| 商品 100% 保真 | 合成图与真实商品照片外观一致，AI 不重绘商品 |
| 首图 100% 合规 | 京东首图规则逐项自动校验，不合规不允许导出 |
| 资产可追溯 | 每张图有主键、来源、提示词、模型、成本、审核状态 |
| 成本可控 | 单 SKU 出图成本 ≤ 2 元，月度用量可见 |

### 2.2 非目标（1.0 明确不做）

| 不做 | 原因 |
|---|---|
| 让 AI 直接生成整张主图 | 家电外观会被"想象"，型号、能效标识、面板细节全错 |
| 按色差抠图 | 白色家电与白底色差只有个位数，必把机身抠掉（已两次失败） |
| AI 生成多角度/爆炸图 | 家电结构复杂，生成的角度是假的，客服拿去答顾客会出事 |
| 用模型写型号/价格/能效文字 | 错一个字就是合规事故，文字一律本地 canvas 排版 |
| 视频素材 | 1.0 先把静态图跑顺，视频另立需求 |

## 4. 视觉设计 1.0

### 4.1 现状盘点（代码事实）

| 项 | 现状 |
|---|---|
| 页面 | `design.html`（主图工作室）、`selling.html`（卖点图）、`comparison.html`（对比图） |
| 合成引擎 | 本地 canvas（`js/design-deal.js`，759 行），商品 + 文字 + 背景全部本地绘制 |
| AI 能力 | `handlers/design.js`：只生成**背景**；DeepSeek 负责把一句话扩写成提示词 |
| 图像服务 | 硅基流动，3 个模型：Kolors（免费）、Z-Image Turbo（约 0.10 元/张）、Qwen-Image（约 0.30 元/张） |
| 场景库 | **8 张内置图**（明亮客厅、暖光客厅、静谧卧室、北欧原木、客厅夜景、白底棚拍、高级灰棚拍、现代办公） |
| 存储 | 文件落 `assets/design/generated/`，最多保留 200 张，超了自动删最旧 |
| 数据库 | **无**（没有资产表、没有任务表、没有用量表） |
| 合规校验 | 京东规则已硬编码（≥800px、纯白底、商品占比 ≥70%、四边留白 30px、≤3MB） |

**结论：合成这一层是好的，缺的是「生产管理」这一层。** 不用重写画布，只要把它包进一个有序的流程里。

### 4.2 用户与场景

| 角色 | 场景 | 频率 |
|---|---|---|
| 运营（主要） | 上新、换季、大促，一个 SKU 出一套图 | 每周 5—20 个 SKU |
| 设计 | 定模板、审图、处理 AI 出不好的图 | 每天 |
| 客服 | 找某型号的图回答顾客 | 随时 |
| 副总 | 看这个月出了多少图、花了多少钱、有没有违规 | 每月 |

### 4.3 功能需求

编号规则：P0 = 1.0 必做；P1 = 1.0 可选（有则更好）；P2 = 下个版本。

#### FR-01 商品图上传与抠图（P0）

- 支持 JPG/PNG，单张 ≤ 20MB，自动纠正方向。
- 两种输入：**透明底 PNG**（直接用）、**白底 JPG**（自动抠图）。
- 抠图走后端服务（BiRefNet 类模型），不依赖色差。
- 输出：透明底商品图 + 边缘质量评分（0—100）。
- 边缘评分 < 70 时提示「建议换白底图或手工修边」，不阻断流程。
- **验收**：白色空调机身抠图后边缘无白边、无缺口；1 张图 ≤ 8 秒。

#### FR-02 京东首图（P0）

- 白底 `RGB 255,255,255`，1200×1200 输出（可切 800）。
- 商品占比 ≥70%，四边留白 ≥30px（1200 图按 45px）。
- 无文字、无 LOGO、无边框、无水印。
- 自动加接触阴影（可关），阴影方向固定左上→右下。
- 一键导出 JPG（质量 90，≤3MB）。
- **验收**：合规清单 6 项全绿才能导出；导出图在京东后台首图检测通过。

#### FR-03 场景图生成（P0）

- 场景来源两层：**内置场景库**（从 8 张扩到 30 张，按房间/风格/时段分类）+ **AI 生成**。
- AI 生成支持「一句话 → 提示词 → 出图」，也支持直接改提示词。
- **模型可选**（见 4.6），默认走性价比模型，正式出图提示切高质量。
- 同一 SKU 一次生成 4 张不同场景候选，人工选 1—2 张。
- 家电专属约束写进提示词模板：不要出现人、不要出现其他品牌、不要虚构尺寸、必须有可放置商品的平面。
- **验收**：一次生成 4 张 ≤ 40 秒；至少 1 张可直接用（不用修）。

#### FR-04 合成与光影（P0）

- 商品叠到背景上，自动做三件事：
  1. **接触阴影**：按背景光源方向生成柔和投影。
  2. **色温统一**：背景偏暖/偏冷时，商品轻微调整白平衡（幅度可调，默认 15%）。
  3. **透视校验**：商品底边与背景的"地面线"角度差 > 5° 时提示。
- 高级选项（P1）：AI 重打光（IC-Light 类），让商品受背景光影响。
- **验收**：合成图不存在"漂浮感"（无阴影）与"贴纸感"（色温断裂）。

#### FR-05 文案排版（P0）

- 文字全部 canvas 绘制，可选字体：思源黑体（本地自托管）。
- 字段：主标题（≤12 字）、副标题（≤20 字）、3 条卖点（每条 ≤10 字）、价格、角标（新品/直降/以旧换新）。
- 自动避让商品区域：文字不压在商品主体上（重叠 > 15% 报警）。
- 型号、能效、容量等**事实字段从产品知识库读取**，不允许手打（防写错）。
- **验收**：改文案不重新生成背景；文字零错字、零溢出。

#### FR-06 平台合规校验（P0）

| 平台 | 规则 | 校验方式 |
|---|---|---|
| 京东 | 首图纯白、≥800px、商品占比 ≥70%、无文字 LOGO 边框、≤3MB | 本地像素检测 + 元数据 |
| 天猫 | 主图 ≥800×800、白底优先、不得拼接 | 尺寸/像素检测 |
| 拼多多 | 主图 ≥480×480、不得有牛皮癣 | 尺寸/文字区域检测 |
| 通用 | 不得出现绝对化用语（最、第一、顶级） | 文案词表 |

- 校验结果逐项显示，红项不允许导出（可强制导出，但记录原因）。
- **验收**：故意上传带文字的图，首图校验必须拦下。

#### FR-07 批量与套图（P1）

- 选 SKU → 选模板（首图+4 场景+活动图）→ 一次排队生成。
- 支持 CSV 导入：型号、标题、卖点、价格，一行一个 SKU。
- 任务可暂停/重试；失败自动重试 1 次，仍失败则跳过并记录。
- **验收**：10 个 SKU × 6 张 = 60 张，全部产出，失败率 < 5%。

#### FR-08 素材库（P0）

- 每张图入库：ID、SKU、用途、尺寸、模型、提示词、成本、创建人、审核状态、文件路径。
- 支持按 SKU / 型号 / 用途 / 日期筛选，支持"复用这张背景"。
- 一个 SKU 的图聚成一组，可整组下载 ZIP。
- 保留策略：默认永久保留，按租户配额（如 20GB）提示清理。
- **验收**：三个月前的图能按型号搜到并复用。

#### FR-09 审核与状态（P1）

- 状态机：草稿 → 待审 → 通过 → 已归档；不通过需填原因。
- 设计/运营可提审，admin 或设计负责人可审。
- 通过后才允许"标记为可上架"。
- **验收**：未通过的图不能出现在"可上架"列表。

#### FR-10 用量与成本看板（P1）

- 本月：生成张数、成功/失败、花费（元）、按模型拆分、按人拆分。
- 单张均价、单 SKU 均价。
- 预算阈值：超过月预算 80% 时首页提示。
- **验收**：数字与实际账单误差 < 5%。

#### FR-11 降级与容错（P0）

- 模型不可用 → 自动切备用模型（Seedream → Qwen-Image → 内置场景）。
- Key 未配置 → 只用内置场景，不报错，页面提示"AI 未开通"。
- 生成超时 → 返回任务 ID，前端可继续等，不卡界面。
- **验收**：拔掉 Key 后，首图与内置场景仍可正常出图。

### 4.4 页面结构（1.0）

保持三页不变，主图工作室改成"四步走"：

```
① 选商品（型号/SKU） → ② 选套图模板 → ③ 生成与挑选 → ④ 校验与导出
```

- 顶部：SKU 搜索 + 当前额度（本月已用/预算）。
- 左侧：步骤条；右侧：预览画布（实时）。
- 底部：素材库入口（抽屉），可把历史背景拖回来复用。

### 4.5 家电 3C 专属规则（写进提示词与校验）

| 品类特性 | 规则 |
|---|---|
| 白色/银色高反光 | 背景避免纯白与强反光面；棚拍背景用 18% 灰或浅木色 |
| 比例失真敏感 | 柜机高度、挂机宽度必须按真实尺寸比例，画布给出参考线 |
| 安装场景强 | 挂机必须有墙面与室内机位；柜机必须有客厅角落与地面 |
| 型号/能效标识 | 永不生成，只用真实照片；文案字段从知识库取 |
| 竞品与品牌 | 提示词禁止出现其他品牌 LOGO、文字、可比产品 |
| 季节营销 | 场景库按"夏季制冷/冬季制热/以旧换新"打标签 |

### 4.6 模型选型

#### 4.6.1 候选与价格（2026-10 官方价）

| 模型 | 接入方式 | 价格（元/张） | 优势 | 短板 |
|---|---|---|---|---|
| **Seedream 5.0 Pro** | 火山方舟 | 0.30（≤261 万像素）/ 0.60（更大）；**图层拆分 0.15/0.30** | 中文理解最好，光影与材质强，组图一致性（同批 9 张），支持图层拆分 | 单价最高 |
| Seedream 5.0 Lite | 火山方舟 | 0.22 | 质量接近 Pro，便宜 27% | 细节略弱 |
| Seedream 5.0 Flash | 火山方舟 | 0.12 | 极快，适合试稿 | 不适合终稿 |
| Seedream 4.5 | 火山方舟 | 0.25 | 稳定、崩图率低 | 已被 5.0 覆盖 |
| **Qwen-Image-3.0** | 阿里百炼 | 0.18；Pro 0.25（1K）/0.50（2K） | 中文文字与结构强，编辑一致性提升，便宜 | 摄影质感略逊 Seedream |
| Qwen-Image-2.1 Turbo | 千问 API | 0.10 | 便宜、快（8 步） | 权重仅研究许可，商业需授权；画质不稳 |
| 万相 2.5 图像编辑 | 阿里百炼 | 0.20 | 换背景/局部改稳定 | 生成不如前两者 |
| 混元图像 3.0 | 腾讯 | 按量 | 开源可私有化，中英文字好 | 商用摄影质感偏弱 |
| Flux.2 Klein / Z-Image Turbo | 自建 GPU | 电费 | 可控、可微调、数据不出门 | 需显卡与运维，出图稳定性靠调 |
| Nano Banana Pro / GPT Image 2 | 海外 | $0.03—0.15 | 编辑与一致性最强 | 国内接入不稳定，不适合做主链路 |

#### 4.6.2 结论（1.0 选型）

| 环节 | 选型 | 理由 |
|---|---|---|
| 抠图 | BiRefNet 类（后端服务） | 白电边缘最稳，不依赖色差 |
| 背景生成（主） | **Seedream 5.0 Pro** | 家电材质（拉丝金属/高光塑料）与中文场景描述最稳；0.30 元/张可接受 |
| 背景生成（备） | **Qwen-Image-3.0** | 便宜 40%，中文强，作为降级与批量草稿 |
| 试稿 | Seedream 5.0 Flash（0.12） | 一次出 6 张让运营选，选定后同参数出终稿 |
| 局部修改（P1） | Qwen-Image-3.0 编辑 / 万相 2.5 i2i | 去掉多余物体、扩图 |
| 重打光（P1） | IC-Light（自建） | 让商品与背景光向一致，解决"贴纸感" |
| 超分 | Real-ESRGAN（自建） | 1200/2000 输出清晰 |
| 文字 | 本地 canvas | 永不交给模型 |

**一句话：背景可以用模型，商品和文字不行。** 这条铁律 1.0 不变。

| 项目 | 单 SKU | 月 100 SKU |
|---|---|---|
| 首图（本地合成） | 0 元 | 0 元 |
| 场景图 4 张（Seedream 5.0 Pro） | 1.20 元 | 120 元 |

### 4.7 技术方案（实现约束）

| 层 | 方案 | 说明 |
|---|---|---|
| 前端 | 沿用原生 JS + canvas | 不引框架，符合现有约定 |
| 接口 | 扩 `handlers/design.js`：`assets` / `jobs` / `generate` / `compose` / `verify` / `usage` | 与现有 `api/design` 同一入口 |
| 任务 | 进程内队列 + DB 状态机（单机够用） | 不做微服务；重启后未完成任务标失败可重试 |
| 图像服务 | `lib/design/provider.js` 改成多 provider 注册表 | 火山方舟 + 阿里百炼 + 硅基流动，按能力路由 |
| 存储 | 本地 `assets/design/` + DB 元数据 | 云部署时降级为对象存储（先不做） |
| 抠图 | 新增 `lib/design/matting.js` | 调用抠图 API 或本地模型；失败降级"白卡展台"（现有方案） |
| 配置 | `.env.local` 加 `ARK_API_KEY` / `DASHSCOPE_API_KEY` | Key 不进浏览器、不进 git |
| 审计 | 每次生成写一行 `design_usage` | 谁、什么模型、多少钱、成功与否 |

#### 4.7.1 数据表（3 张新表，迁移 0014）

| 表 | 关键字段 |
|---|---|
| `design_assets` | id、tenant_id、sku、model_no、purpose（首图/场景/活动）、width、height、file_path、prompt、model、cost、status（草稿/待审/通过/归档）、created_by、created_at |

### 4.9 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| AI 把商品"改样子" | 图片与实物不符，售后纠纷 | 商品永不进生成模型，只走合成；图层拆分仅用于背景侧 |
| 白色家电抠图带白边 | 首图被判不合规 | 抠图后做边缘收缩 1px + 白边检测，不合格提示换图 |
| 平台判"图片拼接" | 违规下架 | 场景图只做 2—5 张副图，首图永远纯白底单张 |
| 成本失控（有人连点） | 费用超支 | 4 秒节流 + 任务配额 + 月预算提示 |
| 模型涨价/下线 | 功能中断 | provider 注册表 + 备用模型自动切换 |
| 生成内容含他人品牌 | 侵权 | 提示词黑名单 + 出图后 OCR 检测品牌词 |

## 5. 开源对标（本次检索结论）

### 5.1 项目清单

| 项目 | 类型 | 主要功能与特点 | 我们借鉴什么 | 不借鉴什么 |
|---|---|---|---|---|
| **comfyanonymous/ComfyUI** | 生成底座 | 节点式工作流，可复现、可分享，社区插件最多 | 工作流即配置，便于复现同一套参数 | 直接给运营用，门槛太高 |
| **yolain/ComfyUI-Yolain-Workflows** | 工作流合集 | 含「电商产品主图」实战流程，覆盖抠图→背景→合成→放大 | 节点组合与参数区间 | 依赖本地 GPU |
| **Peterwong666/comfyui-ecommerce-vision** | 生产线封装（2026-09 启动） | 把工作流封成场景模板，加任务队列、批量、良品率度量、成本核算、素材管理 | **产品结构最值得抄**：任务队列 + 成本核算 + 良品率 | 自建 GPU 运维 |
| **zhuqquan-dot/e-commerce-ai-image-platform** | 生产级平台 | 商品输入→平台规则适配→批量→质检→导出，内置 10+ 平台尺寸 | 平台规则引擎、质检清单 | 多平台规则全做（我们只做 3 个） |
| **xianyu110/ecommerce-image-skills** | Agent Skills | 12 个技能：白底、场景、卖点、尺寸图、长图、批量换色；先锁定形状/颜色/Logo/文字再生成 | **"锁产品特征"写进提示词**、平台规则（白底 #FFFFFF、主体 ≥85%） | 依赖通用大模型直接出整图 |
| **Weixiaoduo/ecom-details-image** | 场景模板 | 25 种电商模板（主图、生活场景、平铺、细节、Banner） | 模板分类法 | 纯提示词，无合成 |
| **mkhsu2002/EC-Designer** | 素材包生成 | 策略→8 张套图→先审文案再出图→批量下载 | **"先审文案再出图"的流程** | 全 AI 出图 |
| **ZhengPeng7/BiRefNet** | 抠图模型 | 发丝级抠图，边缘细节强 | 白电边缘的主力方案 | — |
| **lllyasviel/IC-Light** | 重打光 | 按背景光向给前景重新打光 | 解决合成"贴纸感" | 1.0 暂不上 |
| **Sanster/IOPaint** | 消除/重绘 | 去水印、去杂物、局部重绘 | 商品图去瑕疵 | — |
| **layerdiffusion** | 透明图层 | 直接生成带 alpha 的图像 | 背景分层（P2） | 1.0 不用 |

### 5.2 三条结论

1. **家电 3C 专属的开源项目几乎没有**。现有项目 90% 面向服装/百货，家电的高反光、白机身、尺寸比例、安装场景都要自己写规则。所以策略是「通用项目抄结构 + 家电规则自建」。
2. **开源项目真正成熟的是"生产管理"，不是"画质"**。任务队列、批量、良品率、成本核算、素材管理这几件，比换更贵的模型更能提升实际产能。
3. **行业共识和我们一致**：做得好的工具（含开源项目）都把商品和文字排除在生成之外，只生成背景。这条不用改。
