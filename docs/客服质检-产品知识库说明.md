# 产品知识库（客服管理）

> 页面 `/products.html`，接口 `/api/product-knowledge`，口径版本 `product-advice-v1`。
> 定位：把商品详情页变成**可核对的事实**，再拿这些事实去纠正客服答复。
> 它不参与打分，也不改复核结论——只回答「这句话应该怎么答」。

## 一、它解决什么问题

质检回答「这单几分」，消费者洞察回答「顾客在问什么、我们哪里没答好」，本页回答第三件事：
**顾客问到了这台机器的具体东西，客服答的到底对不对**，并给出可以直接发给顾客的说法。

例子（真实会话）：

> 顾客：我看宣传有防直吹，自清洁，这些都在哪体现呢
> 客服：遥控器关机后同时按"灯光"和"辅热"约 2 秒就能开启自清洁……（只讲了自清洁流程）
> 系统建议：防直吹是冷风贴着天花板吹出去，不往人身上打——**这条客服完全没答**

## 二、三个分组

| 分组 | id | 型号写法 |
|---|---|---|
| 格力空调 | `gree-ac` | `KFR-35GW/NhAa1BAj`、`KFR-72LW/...` |
| 海尔空调 | `haier-ac` | `KFR-35GW/B5LAA21U1` |
| 海尔冰箱 | `haier-fridge` | `BCD-501WGHFD14S8U1` |

分组 id 与销售结构页一致，所以「这台机器卖得怎么样」和「这台机器客服答得怎么样」能对上。

## 三、怎么导入

有两条通道，按手里有什么资料选：

### 通道 A：产品参数表（整批，一次几十个型号）

客服主管整理的《格力产品参数一览表》（横向矩阵：一列一个系列、一行一个参数）走「导入参数表」：

1. 选分组 → 选 `.xlsx` → 解析预览：系统把「一列一个系列」转置成「一台机器一条记录」。
2. 逐行核对（勾选/取消、点「看明细」看全部参数）→ 保存入库。
3. 同型号已在库里时状态列标「合并」，保存后参数以这次为准、卖点只增不删。

转置规则（`lib/product/gree-table.js`）：

| 情况 | 处理 |
|---|---|
| 一列两个型号（1 匹 / 1.5 匹两行，或挤在一格） | 拆成两条记录，参数按位次分配 |
| 一格塞两个值（`2600/3500`、`2660W/3520W`、`710m3/h/800m3/h`） | 两段都是「数字+单位」才拆；1 匹取前、1.5 匹取后 |
| 单型号的列却写了双值（另一台在别的列） | 原样保留 + 标「待核实」，不替人猜 |
| 能效一格混写（`一级/APF5.28/5.27`） | 拆成「能效等级」+「APF 能效比」两条 |
| 值为 `/`、`—` | 不入库（不确定是「不支持」还是没填） |
| `是/否/√/×` | 译成「支持/不支持」 |
| 嵌入图片（内外机尺寸、机器图片等） | 读不到，预览时明示缺哪些项 |
| 「推荐理由」等内部评价 | 不进对客口径 |
| 京东素材码 `#E-s66`、`<br/>`、表情符号 | 清掉 |
| 表里已知的抄写错误 | 有修正表（漏 K 的京韵3级、h→Nh 的云佳Pro、内机代号与前缀打架的凉之夏、云锦Ⅲ 柜机型号），修正需客服主管确认 |

2026-10-27 首次导入结果：**66 个型号 / 1721 条参数 / 526 条卖点**，待人工核实 2 条（明珠、时光序的外机净重双值）。
「节能王子Pro（2025）」一列只有零散卖点、无型号，已跳过，等补齐后再导。
14 个型号卖点为 0（云佩、京淳、京致、云铂、臻新风、云逸1级、冷静王+ 等）——卖点表里没有这些系列，需用通道 B 或手动补。

### 通道 B：详情页（单个型号，适合参数表没有的新品）

1. 打开商品详情页 → 全选（Ctrl/⌘+A）→ 复制整页 → 粘进「导入产品」。
2. 选分组 → 提取预览 → 核对型号和数字 → 保存入库。
3. 也可以选择 `.txt / .html` 文件导入（页面直接读文本，不上传服务器）。

**为什么是「复制正文」而不是填链接**：京东/天猫详情页对服务器抓取有风控，直接抓大概率拿到登录页或验证码，
识别质量不如人工复制一次。纯图片详情页识别不到内容，会提示改为手动新建。

### 提取与核验（重要）

有 DeepSeek Key 时由模型读原文，**每条事实必须带 evidence（原文片段）**，落地前逐条回原文核对：

| 内容 | 原文找不到时 |
|---|---|
| 参数（数字类） | **丢弃**——数字写错比不写更危险 |
| 售后口径（保修/安装收费） | **丢弃**——政策说错会直接引发纠纷 |
| 卖点 | 保留，标「待核实」——措辞允许概括 |
| 外观 | 丢弃 |
| 型号 | 改用原文正则识别出的写法；型号大小写按详情页显示，判重时忽略大小写 |

没有 Key 或调用失败时走**规则解析**：型号、参数、外观靠正则和「名称：值」行，卖点只认关键词行。
页面会明确写出这次是「AI 提取」还是「规则解析」。

### 同型号再导入 = 合并，不是覆盖

- 参数：按名字对齐，**以这次识别为准**（详情页更新了就更新）。
- 卖点：按标题对齐，**新的补进来，旧的保留**。
- 人工改过的条目（`manual=true`）：**任何情况下都不覆盖**。

## 四、关联会话怎么算

只用两类证据，不做语义猜测：

1. **型号命中**（最强）：顾客或客服提到这个型号，含拆开片段（`KFR35GW`、`NHAA1BAJ` 都算）。
2. **卖点关键词命中，但只看顾客说的话**——客服的标准话术里几乎每条都写着「自清洁、防直吹、变频」，
   用全文匹配会让每一通售前对话都命中每一台机器，等于没筛。

门槛：型号命中直接算；没有型号时至少 2 个顾客侧关键词。
通用词（变频、智能、送风、冷风…）**不能**当卖点关键词，见 `lib/product/groups.js` 的 `GENERIC_KEYWORDS`。

> 结论：关联是**疑似**，命中词会显示出来，请点开核对；没有型号命中的，务必先确认是不是这台机器。

## 五、修正建议的口径

两步，顺序不能反：

1. **确定性骨架**（不花钱、可复现）：顾客那句话提到了哪些事实 → 客服下一条回复有没有答到
   （参数比对数值，卖点比对标题/关键词）→ 得出覆盖率。
2. **模型写话**：只让它把骨架翻译成能直接发给顾客的 1-2 句，并说明缺在哪。

三道防幻觉：

| 闸 | 规则 | 不通过时 |
|---|---|---|
| 建议必须挂 `factRef` | 指向知识库条目名 | 丢弃 |
| 顾客原话必须真提到这件事 | 防「顾客问插座，你该补讲变频」 | 丢弃（记「硬扯」） |
| 建议里的数字必须能在资料或会话里找到 | 防编参数 | 保留但标「待核实」 |

另外两条务实规则：

- 「没答到」要求**整段会话都没答到**；客服前面讲过、顾客又问一次的，不算没答。
- 同一卖点只出一条建议，不按提问次数重复。

结论只有四种：`没答到 / 答错了 / 太含糊 / 答到了`。**不给客服打分**，分数仍由质检口径决定。

## 六、成本与边界

- 一条建议约 2000-3000 token 输出，实测 3-9 秒；同一「会话 × 型号」结果落库缓存，重看不重复花钱，
  点「重新生成」才会再算。
- 只对**确实提到这台机器**的会话生成建议，不会全量批跑。
- 不做的事：不抓竞品、不写营销文案、不判断「哪台更值得推」、不替代质检评分。

## 六、官方主数据表导入（2026-10-27 新增）

数据源：从格力官方系统导出的《挂式空调-*.xlsx》（一行一个主数据 SKU）+ 我司《格力空调产品明细.xlsx》（产品系列/物料编码/型号/机型档次）。

导入命令（默认演练，加 `--apply` 才写库）：

```
node scripts/import-gree-master.js <挂式空调-xxx.xlsx> <格力空调产品明细.xlsx> [--apply]
```

规则：
- 主数据表只导「已会签」和「已淘汰」的行；「未会签 / 需处理 / 老国标-待处理」是草稿，跳过。
- 型号从「主数据名称」里抠（「产品型号」列是空的）；颜色括号（珊瑚玉）和「顶」不参与型号匹配，颜色进外观。
- 与库内同型号：**只补缺失参数**（尺寸、装箱清单、匹数等），不覆盖已核对过的值。
- 在售明细按物料编码/型号回填 `materialCode`（物料编码）、`tier`（机型档位）、`shopSeries`（在售系列）；库里没有的建骨架记录（只有编码/档位/系列，参数为空）。
- 数据字段：`data.materialCode / tier / shopSeries`；详情抽屉 meta 行和列表型号旁的档位徽标会显示。
- 解析器：`lib/product/gree-master.js`，测试 `tests/product-gree-master.test.js`。

注意：
- 「产品型号」列全空是正常的，型号在名称里。
- 明细表若同型号出现两个物料编码（如 NhAe1BAj 的 KB634000400/800），脚本取先出现的并在输出里提示，需主管确认哪个对。

## 八、系列名称统一格式（2026-10-28 第二次升级）

全库系列名统一为：**{产品系列名}{三级?}{xx机}({颜色)?}**

规则（用户拍板）：
1. 只留产品系列名（凉之静、睡梦宝、月亮女神…），剥「格力·」前缀；
2. 删 变频/定频/冷暖/挂机/柜机/空调、营销语（「空调」后面的整段）和型号串（KFR-…）；
3. 1级能效删除；3级改写「三级」；2级同理记「二级」；插在系列名与 xx机 之间；
4. 取型号「KFR-」后两位数字命名「xx机」（35机 / 26机 / 72机）；
5. 颜色保留：名称/型号里的括号（珊瑚玉）、裸写颜色词（…FNCa-A3 奢华金）、定频老款「顶 白色」都认；
   「（高端）（线下款式）（含管）(WIFI)（注塑）」这类修饰不当颜色。

例：月亮女神变频冷暖正1.5匹1级能效挂机空调 KFR-35GW/(35579)FNhCc-B1(WIFI)(珊瑚玉) → **月亮女神35机(珊瑚玉)**

- 分销机型（160 条）的系列名是清单 G 列主管核定的，已符合格式，不改动；其余 573 条由「商品标题+型号」重新生成，0 条失败。
- 解析器：`lib/product/series-format.js`（`formatSeries(name, model)`），脚本 `scripts/normalize-series.js`（演练默认、--apply 写库），测试在 `tests/product-gree-distribution.test.js`。以后新导入的记录如需统一，重跑该脚本即可。
